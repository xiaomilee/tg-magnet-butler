# 历史字典

一句话：**记住你下过什么，搜索前先告一声。**
文件删了也不忘——记下「什么时候发现它不在了」，这条记录永久保留，下次再搜同一个东西时会提醒你
「曾经有过，某年某月某日发现已删除」。
**「已存在」和「曾存在已删」都默认拦下投递，发 `/force 关键词` 才继续。**

---

## 1. 它到底记什么

对每个监控目录往下走（默认 3 层），记两类东西：

| 类型 | 例子 | 用途 |
| --- | --- | --- |
| 文件夹 | `FC2PPV-4999948 某作品/` | 通常一个作品一个文件夹，**命中率最高** |
| 文件 | `ABC-123 甲.mkv` | 有些人是散装放的，靠文件名兜底 |

每条记录存：路径、名字、归一化名、去扩展名与副本尾巴的名字、体积、层级、首次记录时间、
最近一次看到的时间、状态（`present` / `deleted`）、**发现删除的时间**、累计消失次数。

不记的东西（可在配置里改）：隐藏目录（`.xxx`）、系统目录（`@eaDir`、`#recycle`、`lost+found`、
`System Volume Information`）、下载中间态（`.part`/`.aria2`/`.!qB`/`.crdownload` 等）。

---

## 2. 一次分析做了什么

```
读配置里的目录
   │
   ├─ 目录不存在 / 读不了 ──→ 记一条警告，这个目录**一条都不标删除**（防止卷没挂上误清）
   │
   ├─ 遍历 → 得到当前快照（路径集合）
   │
   ├─ 与库里上一份记录逐个对比
   │     ├─ 新路径 ───────────→ 插入，first_seen = 现在
   │     ├─ 已有且仍在 ───────→ status=present，last_seen = 现在
   │     └─ 已有但现在没有 ───→ status=deleted，deleted_ts = 现在（**记录不删**）
   │
   ├─ 目录还能读，但条目比上次少了 60% 以上 ──→ 判为「疑似不可访问」，
   │     只警告、不标删除（防权限变化、防挂载点为空目录）
   │
   └─ 写一条扫描流水（新增/消失/恢复/耗时），供面板显示「上次分析」
```

两个刻意的设计：

* **`deleted_ts` 是「发现时间」不是「删除时间」。** 程序没有文件系统审计能力，只能记录自己
  哪一次扫描发现它不在了。报告和回复里都写「发现已删除」，不写「删除于」。
* **恢复不清零。** 文件删了又下回来，状态回到 `present`，但 `deleted_ts` 与 `deleted_count`
  继续保留。所以你仍然能看到「这东西以前删过一次」。

## 3. 命中怎么判

搜索时（整段检索与 FC2 编号检索都会）拿这些词去比：

1. 这次实际发给站点的查询串（FC2 分支就是 7 位编号）
2. 分拣出来的关键词
3. 消息第一行（去掉磁力后的标题行）

比对方式：**先把两边都归一化**——转小写、全角转半角、去掉所有标点与空白，只留字母数字与汉字。
所以 `ABC-123 甲.mkv`、`abc123甲`、`ABC_123-甲` 是同一个东西。

打分：

| 情形 | 分数 | 说明 |
| --- | --- | --- |
| 归一化名完全相同 | 1.0 | 强命中 |
| 库里的名字是查询词的一部分 | 0.55 ~ 0.95 | 「库里有 `FC2PPV-4999948 某作品`，你搜 `FC2PPV-4999948`」 |
| 查询词是库里名字的一部分 | 0.5 ~ 0.9 | 「你搜一长串，库里有短名」 |
| ≥ 0.75 | 强命中 | 默认触发「跳过投递」 |
| 0.5 ~ 0.75 | 弱命中 | 只提示，不拦 |
| < 0.5 | 不算命中 | |

太短的词不参与比对（中文 < 3 字、英文 < 4 字符），否则「第1集」这种会把整本字典都匹配上。

命中后还会**折叠**：如果命中的是目录，目录里的同名文件就不再重复列出来，报告里只出现一条。

## 4. 命中之后的行为

| 状态 | 回复 | 检索 | 自动投递 |
| --- | --- | --- | --- |
| `present` 且强命中 | `📚 库里已有` + 路径 | **跳过** | **跳过** |
| `present` 但弱命中 | `📚 库里已有`（提示） | 照常 | 照常 |
| `deleted` 且强命中 | `🗑 曾经有，现在没了` + 发现时间 | **跳过** | **跳过** |
| `deleted` 但弱命中 | `🗑 曾经有，现在没了`（提示） | 照常 | 照常 |
| 没有 | 无 | 照常 | 照常 |

`deleted` 与 `present` 待遇一致：**都要 `/force` 才能继续**。理由很直接 —— 记录还在说明这个片子
曾经被下过，删掉多半是主动清理（看过了、腾空间），再一次投递大概率是白下。所以默认拦，
回复里明说「什么时候发现被删的」，由人来决定要不要重下。

跳过时回复末尾会写 `/force 关键词`，用它就能无视字典强制重下。

三个开关（面板 → 历史字典）：

* `检索前先查字典`（`library.check_search`）—— 关掉就完全不查，字典只当档案用。
* `命中「已存在」就不投递`（`library.skip_download`）—— 关掉就只提示、不拦投递。
* `命中「曾存在已删」也不投递`（`library.skip_deleted`）—— 关掉则「已删」只提示、照常投递。

**磁力直投不查字典**：消息里自己带了 `magnet:` 时按「你明确要下」处理，直接投迅雷。
字典只在需要去站点检索的那条路径上生效。

## 5. 疑似重复

按「去扩展名、去 `(1)`/`[2]`/`- 副本`/`copy` 尾巴」的归一化名分组，同一组有两份以上就列出来：

* 组内体积**都相同且非零** → 「同名同体积，基本可以确定重复」
* 否则 → 「名字相同，可能只是不同版本/清晰度」

两条排除规则，避免一堆假警报：

* **目录与它自己内部的同名文件不算重复**（`作品 X/作品 X.mkv` 是正常结构）。
* 文件夹体积由子文件累加得出，所以文件夹之间的重复也能算出「可能白占多少空间」。

重复分析是**只读**的，不会删任何东西，只给提示。

## 6. 配置项

```jsonc
"library": {
  "roots": ["/vol1/1000/Downloads"],  // 监控目录，可多个
  "max_depth": 3,                     // 往下走几层
  "include_files": true,              // 是否连文件名一起记
  "max_items": 20000,                 // 单次扫描条目上限，超出截断并提示
  "skip_hidden": true,
  "ignore_names": [],                 // 留空用内置系统目录黑名单
  "ignore_exts": [],                  // 留空用内置下载中间态黑名单
  "check_search": true,               // 检索前查字典
  "skip_download": true,              // 命中「已存在」就不投递
  "skip_deleted": true,               // 命中「曾存在已删」也不投递
  "dup_min_size_mb": 0                // 查重时忽略小于这个体积的文件
}
```

## 7. 数据表

```sql
library_items   -- 一个路径一行，path 唯一
  root, path, kind(dir|file), name, name_key, base_key, depth,
  size, mtime, first_seen, last_seen, status, deleted_ts, deleted_count

library_scans   -- 每次分析的流水
  ts, roots, scanned, added, removed, restored, present, deleted, duration, detail
```

`name_key` / `base_key` 落库时就算好，查询直接用（`LIKE %关键词%` + 状态排序），
不用每次现算。

## 8. 常见问题

**为什么没记录删除的准确时间？**
文件系统不提供「删除事件」。要精确到秒，得靠 inotify 常驻监听，那会在 NAS 上多开一个长期进程，
还要处理重启期间的漏事件。当前做法是「分析时对比」，所以准确说法是「某次分析发现它不在了」。

**目录很大，扫描会不会很卡？**
`os.scandir` 逐层读，2 万条量级通常几秒内。面板同一时间只允许跑一个分析（连点会返回「正在分析中」），
且有条目上限兜底。真正慢的是机械盘冷数据，第一次扫完后面都是增量对比。

**换了个目录结构，旧记录怎么办？**
记录按绝对路径存。改了目录/改名 = 旧记录标「已删除」+ 新路径新增一条。这正是想要的效果：
告诉你「这个名字以前在别处出现过」。把某个目录从配置里删掉时，它的记录不会被标删除，也不会被清空。

**能删掉字典吗？**
面板没有一键清空（故意的，避免误操作）。要清就停应用后删 `{var}/tmb.sqlite3` 里的
`library_items` / `library_scans` 两张表。

**匹配老是误报「已有」怎么办？**
多半是关键词太短或太常见。把 `check_search` 关掉只用查重，或者把 `skip_download` 关掉改成「只提示」；
也可以在 `library.ignore_names` 里加不想参与匹配的目录名。
