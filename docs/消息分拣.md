# 消息怎么被判定

机器人收到的每条消息（含转发、图配字、相册说明）都先经过 `app/tmb/intake.py`，按固定顺序问三个问题，命中就停。这套顺序是产品需求，写在代码里而不在 `rules.json` 里 —— 规则表管的是「第 3 条分支用什么检索词」，判定本身不该被用户改乱。

```
文本
 │
 ├─ 有 magnet:?xt=urn:btih:… ?  ──是──▶ 直接投递（不联网，最多 3 条）
 │
 ├─ 有 FC2 且后面跟编号 ?       ──是──▶ 只用编号检索（优先 7 位）
 │
 └─ 都不是                     ─────▶ 整段消息 → 关键词分拣 → 检索
```

## 1. 磁力直达

判据：出现 `magnet:?xt=urn:btih:` 且 infohash 合法（40 位 hex 或 32 位 base32）。

* **不联网**：一条消息若能直接投递，就不会再访问 sukebei —— 站点挂了也能用。
* **最多 3 条**（`download.max_magnets`），多个磁力按出现顺序，同一 infohash 只投一次。
* 标题优先取磁力里的 `dn` 参数；没有就用消息里除磁力之外的文字（多行拼起来，例如「FC2PPV-4999948 拥有25万粉丝的知名网红」）。
* 会清理掉这些常见的复制垃圾：
  * 磁力后面粘的中文与全角标点：`…AFC，麻烦下一下` → 只留到 infohash 结尾
  * Telegram/网页转义出来的 `&amp;` → `&`（否则 `dn` 与 tracker 全失效）
  * 大写的 `MAGNET:?XT=urn:btih:` → 统一成小写 scheme
  * 整串里多余的 `&`、`"`、`)` 等尾巴
* **截断的磁力不投**：`magnet:?xt=urn:btih:E8BE27D6` 这种只有 8 位的，投递出去只会换来一堆报错；程序会把它记成「没认出来的一条」，回复里明确写出来，然后按普通文本继续走第 3 条。

回复里没有 `⬇️ 1` 这类按钮 —— 磁力已经投过了，再点就是重复任务。

## 2. FC2 编号

判据：没有可用磁力，但文本里出现 `FC2`（不分大小写），且其后 12 个字符内跟着 5–8 位数字。

支持写法：

| 原文 | 取到的编号 |
| --- | --- |
| `FC2PPV-4999948` | `4999948` |
| `FC2-PPV-1234567` | `1234567` |
| `fc2 ppv 1234567` | `1234567` |
| `FC2PPV_7654321 4K` | `7654321` |
| `【FC2PPV-4999948】` | `4999948` |
| `FC2 123456` | `123456` |

* 一段话里出现多个候选时，**优先 7 位**的那个（FC2 编号普遍是 7 位，6 位的多是年份或时长）。
* 检索词**只有编号**，不会把「拥有25万粉丝的知名网红」一起丢过去；`{raw}` 模板在这里会被忽略。
* `FC2` 后面没有数字（如「FC2 新作」）→ 不算命中，退回第 3 条按整段检索，避免搜一个空编号。
* 编号分支的检索参数（分类、做种下限、`limit`）取自内置的 `fc2` 规则；删掉这条规则也能跑，会退回兜底规则。

## 3. 整段检索

前两条都没命中时，才是原来的老路：`rules.json` 里所有规则算分 → 取最高分那条 → 用它的 `query_template` 与过滤条件检索 → 自动投递第 `pick` 名。

这里的取词顺手改了两处，都是为了番号类标题：

* `ABC-123`、`FC2PPV-4999948` 这类「字母-数字」中间的连接符不再被切开（原来会切成 `ABC` + `123`）。
* 纯数字串只有超过 8 位才丢弃（原来超过 6 位就丢，7 位番号会被误伤）。

## 4. 怎么验证

不用真发 Telegram：

```bash
# 只看判定，不联网
python3 /var/apps/tgmagnet/target/main.py --parse "FC2PPV-4999948 某标题"

# 带磁力的原文
python3 /var/apps/tgmagnet/target/main.py --parse "$(printf 'FC2PPV-4999948\n某标题\nmagnet:?xt=urn:btih:E8BE27D6280895F4838832CF84D90451B69B3AFC')"

# 真跑一遍（会检索 + 投递）
python3 /var/apps/tgmagnet/target/main.py --parse "FC2PPV-4999948 某标题" --send
```

面板也能看：搜索测试 → 粘进输入框 → **解析后搜**。判定、取到的磁力/编号、真正发给站点的查询串、
命中的规则会一起摆在输入框下面，然后按这条查询和规则里的条件真搜一次；
自带磁力的消息不发任何检索请求，只把磁力列出来等点「投递」。

| 接口 | 干什么 | 会不会联网 |
| --- | --- | --- |
| `POST /api/intake` | 纯判定（判定 + 查询串 + 命中规则） | 不会 |
| `POST /api/search/parsed` | 判定 + 用判定出的查询真搜一次 | 会（自带磁力时不搜） |
| `POST /api/search` | 直接搜索：把框里的字原样当关键词 | 会 |

## 5. 测试覆盖

`tests/test_intake.py` 20 项，其中用户给的原始样本被当成固定用例：

```
FC2PPV-4999948
拥有25万粉丝的知名网红
magnet:?xt=urn:btih:E8BE27D6280895F4838832CF84D90451B69B3AFC
```

断言它必须走磁力直达、不调用检索（把 `Pipeline.search` 换成会抛异常的桩），并且回复里注明「另有 FC2PPV-4999948，本次用磁力」。
