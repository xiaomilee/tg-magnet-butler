# sukebei 结果页：磁力链接怎么取

这篇回答两个问题：

1. 列表里**淡绿色的那一行**到底是什么意思；
2. 怎么**直接从页面/接口拿到**那一行的磁力链接（🧲 图标指向的地址）。

结论基于站点开源代码（`nyaadevs/nyaa`）的模板与模型，不是靠肉眼猜版面。

---

## 1. 绿底行 = 可信发布者，不是「最热门」

站点把行状态直接写在 `<tr class>` 上（`nyaa/templates/search_results.html`）：

```jinja
<tr class="{% if torrent.deleted %}deleted{% elif torrent.hidden %}warning
           {% elif torrent.remake %}danger{% elif torrent.trusted %}success
           {% else %}default{% endif %}">
```

对照表：

| 行的 class | 颜色 | 含义 | 能不能下 |
|---|---|---|---|
| `success` | 淡绿 | `trusted`——上传者是站点认证的**可信发布者** | 能，通常质量更靠谱 |
| `danger` | 淡红 | `remake`——重制/合集，与原标题不完全对应 | 能，但内容可能不是你找的那份 |
| `warning` | 淡黄 | `hidden`——被管理员隐藏 | 不建议 |
| `deleted` | 灰 | 记录已删除 | 不能 |
| `default` | 白 | 普通上传 | 能 |

注意：**绿色和做种数无关**。你截图里那一行做种只有 9，比它上面的 30 少得多（那几条是 `default`）。绿底只是「这个上传者是站点信任的人」，所以它经常同系列、自己压片、文件更规整。

程序里的处理：绿行加分（`search.trusted_bonus`，默认 10），红行扣 3 分，隐藏行扣 15 分，`deleted` 行直接丢弃。做种数仍占最大权重（上限 40 分），所以不会被绿行挤掉真正做种多的资源。

## 2. 磁力在哪一列

结果表是 9 列：分类 / 名称 / 评论 / **Link** / 体积 / 日期 / 做种 / 吸种 / 完成。

Link 列里最多两个 `<a>`：

```html
<td class="text-center">
  <a href="/download/3002.torrent"><i class="fa fa-download"></i></a>   <!-- 种子文件 -->
  <a href="magnet:?xt=urn:btih:11112222...&amp;dn=...&amp;tr=...">
     <i class="fa fa-magnet"></i>                                       <!-- 🧲 磁力 -->
  </a>
</td>
```

磁力 URI 由站点 `_create_magnet()` 拼成，格式固定：

```
magnet:?xt=urn:btih:<40位十六进制>&dn=<标题>&tr=<tracker1>&tr=<tracker2>…
```

最多带 5 个 tracker，`dn`、`tr` 都做过 URL 编码（空格是 `%20`，不是 `+`）。

### 坑：`&` 被转义成 `&amp;`

Jinja 模板自动转义，页面源码里实际是：

```
href="magnet:?xt=urn:btih:1111...&amp;dn=%2B%2B%2B%20Shop&amp;tr=udp%3A%2F%2F..."
```

如果直接把这个字符串交给下载器，`xt` 还能用（它在最前面），但 `dn` 会变成 `amp;dn`、tracker 全丢，DHT 之外没人给你供源。**取到后必须 `html.unescape()`**。本项目的 `parse_html()` 就吃在这上面过——1.0.2 已修。

## 3. 三条取法，优先级从高到低

### ① RSS 通道（最稳，首选）

```
https://sukebei.nyaa.si/?page=rss&q=4595758&c=0_0&f=0
```

RSS 里没有 magnet，但有 infohash：

```xml
<item>
  <title>…</title>
  <link>https://sukebei.nyaa.si/download/3002.torrent</link>
  <guid>https://sukebei.nyaa.si/view/3002</guid>
  <nyaa:infoHash>1111222233334444555566667777888899990000</nyaa:infoHash>
  <nyaa:seeders>9</nyaa:seeders>
  <nyaa:trusted>Yes</nyaa:trusted>
</item>
```

自己拼磁力即可，不用碰 HTML，不受页面改版/Cloudflare 人机验证影响：

```python
magnet = "magnet:?xt=urn:btih:%s&dn=%s" % (infohash, quote(title))
```

`<nyaa:trusted>Yes</nyaa:trusted>` 就是绿底那一行的标记，RSS 里同样有。

### ② HTML Link 列（RSS 不可用时的兜底）

按行扫，先看 `<tr>` 的 class 判断状态，再取 Link 列里 `href` 以 `magnet:` 开头的那个：

```python
for attrs, row in re.findall(r"<tr\b([^>]*)>(.*?)</tr>", html, re.S | re.I):
    trusted = "success" in (re.search(r'class="([^"]*)"', attrs) or [""])[0]
    for href in re.findall(r'href="([^"]*)"', row):
        href = html_lib.unescape(href)          # ← 关键，别漏
        if href.startswith("magnet:?") and "btih:" in href:
            ...
```

### ③ 种子文件反推 infohash（最后手段）

某行只有 `/download/<id>.torrent`、没有 magnet 时：把种子文件下载下来，取 bencode 里 `4:info` 那一段的**原始字节**做 SHA1，就是 infohash。

要点是「原始字节」——不能用解析后的结构重新编码，键顺序和整数写法一变，哈希就变了：

```python
def info_hash(blob: bytes) -> str:
    i = blob.find(b"4:info") + 6
    end = _bencode_end(blob, i)          # 找到这个 dict 的结束位置
    return hashlib.sha1(blob[i:end]).hexdigest().upper()
```

本项目没有走这条路（Link 列的 magnet 一直都在），但 `parse_html()` 会把 `torrent_url` 一并留下来，需要时可以直接用种子文件投递。

## 4. 本项目的实现与自检

代码在 `app/tmb/nyaa.py`：

- `parse_rss()` —— 通道 ①，从 `<nyaa:infoHash>` 拼磁力；
- `parse_html()` —— 通道 ②，读 `<tr class>` 判绿行，`html.unescape()` 后取 magnet；
- `finalize()` —— 补全磁力、补绝对链接、按 infohash 去重；
- `search()` —— 先 RSS 后 HTML，失败按 errno 说人话。

装到 NAS 上后可以直接验证（绕过关键词规则和过滤，只看解析结果）：

```bash
python3 /var/apps/tgmagnet/target/main.py --grab "4595758" --limit 5
```

输出形如：

```
查询：4595758　拿到 5 条（🟢 = 站点绿底行 / 可信发布）

🟢2. +++ FC2-PPV-4595758 …
    做种 9　吸种 1　完成 2　2.4 GiB　1_1
    磁力 magnet:?xt=urn:btih:1111…&dn=%2B%2B%2B%20…&tr=udp%3A%2F%2F…
    种子 https://sukebei.nyaa.si/download/3002.torrent
```

想给机器人加「搜索」指令时，`--grab` 也是最快的排障入口：它只要能出磁力，说明网络、代理、解析三件事都通了。
