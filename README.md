# 磁力管家（tgmagnet）

飞牛 fnOS 应用（x86 / fpk）：**Telegram 机器人收消息 → 关键词自动分拣 → 检索 sukebei.nyaa.si → 分析结果 → 提取磁力 → 投递到 fnOS 里的迅雷下载**。

整个程序是纯标准库 Python 3，没有 pip 依赖，装进 NAS 就能跑；自带 Web 管理面板。

```
Telegram ──(长轮询)──▶ 机器人
                        │
                        ▼
                  关键词分拣（rules.json）
                        │  命中哪条规则，就用它的检索参数
                        ▼
              sukebei.nyaa.si（RSS 主通道 / HTML 兜底）
                        │  infohash → 补全 magnet
                        ▼
              结果分析（做种 / 热度 / 新鲜度 / 标题命中）
                        │
                        ▼
        迅雷 panel API ／ 飞牛网关 ／ aria2 ／ qB  ← 失败自动降级
                        │
                        ▼
                  回复 Telegram（含按钮换条目）
```

## 1. 功能一览

| 能力 | 说明 |
| --- | --- |
| 三级判定 | 消息自带磁力 → 直接投递（不联网）；提到 FC2 → 只拿编号去搜；都没有才按整段取词。顺序写死在 `intake.py`，不受规则表影响 |
| 关键词分拣 | 规则是数据（`rules.json`），命中词支持中文子串；可配分类、排序、做种下限、体积区间、偏好词、排除词、查询模板 |
| 智能取词 | 自动剥掉「求个 / 帮我下 / 谢谢」等口语，抽 `【】` 里的作品名，不会把整句话丢给搜索引擎 |
| 双通道检索 | 优先 RSS（字段全、结构稳），失败自动退回 HTML 结果页解析；Cloudflare 拦截会给出明确提示 |
| 结果打分 | 做种数、完成量、发布时间、标题命中率、可信发布/重制、偏好词综合排序，并给出排序理由 |
| 行状态识别 | 读结果行 `<tr class>`：绿底=可信发布者、红底=重制、灰=已删（丢弃）、黄=隐藏（扣分）；机器人里用 🟢 标出 |
| 磁力补全 | RSS 只有 infohash，用固定 tracker 列表拼 magnet；同一 infohash 自动去重 |
| 投递迅雷 | 只接飞牛应用中心的官方「迅雷」套件（网关）；自动解析设备空间，支持多文件种子筛选 |
| 迅雷自动连接 | 启动时自动扫网关端口/应用目录，复用浏览器里的飞牛登录态、从迅雷目录里捞 `pan_auth`，打通就写配置并复测；面板上还有「立即重连」 |
| 多后端降级 | 迅雷失败自动依次尝试 aria2、qBittorrent；都不行就把磁力链接回传到 Telegram |
| 交互按钮 | 每条结果可单独投递、重新搜索、查看全部磁力 |
| 去重 | 同一 infohash 在 N 天内不重复投递 |
| 历史字典 | 手动分析指定目录，记住见过的文件夹/文件名；文件消失时记下「发现时间」且**记录永久保留**；搜索命中「已存在」或「曾于某时被删」都提示并拦下，要 `/force` 才继续；可分析同名重复文件 |
| 代理 | **一处填、一行一条**（最多 7 条），不分主备：从上往下试，这条不通自动换下一条，全都不通才走直连；线路**互为备胎**，正在用的那条还通就不换；后台每 3 分钟自动测一次，也能手动「测速并切换」；每条后面直接写结果，失败的那条 5 分钟内排到队尾 |
| Web 面板 | 概览（状态卡片 + 快捷开关 + 迅雷「立即重连」+ 最近投递（单条/多选复制磁力））/ 关键词规则（可视化 + JSON）/ 搜索测试（大输入框、直接搜·解析后搜两条路、解析结果面板、一键粘贴）/ 历史字典 / 下载与迅雷 / 设置 / 实时日志；**手机端自适应**（抽屉菜单 + 底部两格标签栏 + 表格折卡 + 单行顶栏，顶栏随页面滚动） |

## 2. 安装

### 2.1 打好的包直接装

不想自己打包就去 [Releases](https://github.com/xiaomilee/tg-magnet-butler/releases) 下载对应版本的
`tgmagnet_<版本>_x86.fpk`；要从源码出包：

```bash
./build.sh                 # 产出 dist/tgmagnet_<manifest 里的版本>_x86.fpk
```

飞牛 → **应用中心 → 手动安装 → 选择 fpk**。安装向导里填 Bot Token（也可以先跳过），装完桌面会出现「磁力管家」图标。

### 2.1.1 覆盖安装装不上

先看应用中心弹的是什么：

| 弹窗原文 | 原因 | 怎么修 |
| --- | --- | --- |
| 已安装相同或更高版本 | `manifest` 的 version 没涨，或带了后缀（`1.0.2b6` 会被当成 `1.0.2`） | 用纯数字三段式，比已装的大 |
| 安装包无效 / 校验失败 | `manifest` 里某个字段超长（`changelog` 逐版累加最常踩） | 只在 `changelog` 留最近两版摘要，完整历史放 `docs/更新日志.md` |
| 安装成功但服务起不来 | 包内入口缺执行位 / 代码导入失败 | 跑 `python tools/build_fpk.py`，它会打开包复核，不通过就删掉产物 |

`build_fpk.py` 现在自带体检：必填字段、version 格式、`changelog` ≤1500 字节、`manifest` ≤4096 字节、
无 BOM/CRLF；打完还会解开 `app.tgz` 复核 `main.py` 和 `cmd/*` 的执行位。

实在装不上，SSH 到 NAS 直接装一次，它会打印真实原因：

```bash
sudo appcenter-cli install-fpk /vol1/1000/下载/tgmagnet_1.0.18_x86.fpk
```

覆盖安装不会动 `/var/apps/tgmagnet/var`（数据库、配置、日志都在里面）。真想卸载重装，
先把 `var/` 和 `etc/config.json` 备份出来——飞牛卸载可能连私有目录一起清掉。

### 2.2 自己打包

需要 Python 3（打包用，NAS 上不需要 Pillow）：

```bash
python tools/make_icons.py     # 生成图标（需要 Pillow）
python tools/build_fpk.py      # 产出 fpk
```

`fnpack` 也能用（飞牛自带），但本仓库的打包脚本会精确设置 `cmd/*` 的执行位、按官方结构组装，且能进 CI。

### 2.3 手工部署（不用 fpk）

```bash
# 在 NAS 上
mkdir -p /vol1/@appdata/tgmagnet/{etc,var/logs}
cp -r app /vol1/@appcenter/tgmagnet
TRIM_APPDEST=/vol1/@appcenter/tgmagnet \
TRIM_PKGETC=/vol1/@appdata/tgmagnet/etc \
TRIM_PKGVAR=/vol1/@appdata/tgmagnet/var \
python3 /vol1/@appcenter/tgmagnet/main.py
```

管理面板：`http://NAS_IP:8470`

手机上直接用浏览器打开同一个地址即可（面板监听 `0.0.0.0`，同一局域网就能访问），
从飞牛 App 的应用入口进也行。手机会自动切成抽屉菜单 + 底部标签栏的布局，详见 [3.2 用手机打开](#32-用手机打开)。

## 3. 配置 Telegram 机器人

1. 找 [@BotFather](https://t.me/BotFather) 发 `/newbot`，拿到 `123456789:AA...` 形式的 token。
2. 面板 → 设置 → 填 Bot Token → 保存 → 点「重连机器人」。
3. 私聊机器人发 `/id`，把返回的 chat_id 填进「允许的 chat_id」，再保存（留空表示不限制，不安全，不建议）。
4. 发 `/help` 看用法。

> 群聊里要先把机器人拉进群，并在 BotFather 里用 `/setprivacy` 关掉隐私模式，否则机器人收不到普通消息。

> **网络前提（先看这条）**：Telegram API 与 `sukebei.nyaa.si` 都在墙外，NAS 直连不通时必须在设置 →「代理」里填一行 `http://host:port`（指向 NAS 上可用的 HTTP 代理）。Telegram 收发、站点检索共用这一份地址表，可以一行一条写多条，谁通用谁。程序不内置任何翻墙能力，只负责走你给的代理。

### 3.1 连不上？先跑网络诊断

面板 → 搜索测试 →「更多选项」→ **网络诊断**（或在 NAS 上执行 `python3 /var/apps/tgmagnet/target/main.py --doctor`），会把链路拆成 DNS → TCP → 代理端口 → HTTP 四层逐层测，并给出结论。典型结果与对策：

| 诊断结果 | 含义 | 怎么办 |
| --- | --- | --- |
| `连接被拒绝`（errno 111），毫秒级 | 目标端口没有服务在监听 | 代理没启动、端口填错，或填成了 socks 端口 |
| `连接超时` / `连接被重置` | 典型被墙表现 | 换一个能出海的代理出口 |
| `域名解析失败` | DNS 不解析 | 检查 NAS 的 DNS，或代理地址改用 IP |
| `代理端口连通` √ 但 `站点 HTTP 经代理` × | 代理在跑，但出口到不了站点 | 换节点；或代理规则没覆盖该域名 |
| 环境变量代理提示 | 程序在你没填代理时沿用了 `http_proxy` | 要么清掉该变量，要么在设置里显式填代理 |

两个易踩的点：

- **只能填 HTTP 代理**。程序用 Python 标准库直连，不支持 `socks5://`。Clash / V2Ray 一般都有 mixed 或 http 端口（常见 7890），填那个。填 socks 端口会看到「连接被拒绝」。
- **内网地址自动绕过代理**。迅雷网关 `127.0.0.1:5666`、aria2、qBittorrent 这些本地调用不走代理，不用另配 NO_PROXY。

### 3.2 一条代理不够稳？多写几行，谁通用谁

面板 → 设置 → **代理**：只有一个框，**一行一个地址**，从上往下试。

```
http://192.168.1.11:7890
http://192.168.1.10:7897
```

- Telegram 和检索站**共用这一份**，不用再分别填（以前填两遍，改一处得先找它在哪）；
- 最多 7 条，第一行到最后一行**没有主次**，只是尝试顺序；
- 全都不通才走**直连**；一行都不填 = 直接直连；
- 最实用的填法：本机 Clash 一行、隔壁开着 Clash 的电脑一行（Verge 默认 mixed 端口 7897）。
  电脑关机、换端口、节点被墙，程序自己换下一条，不用爬起来改配置。

**互为备胎**：现在走哪条就一直走哪条，它断了才换人。换的时候按**你写的顺序**挑第一条能用的，
所以排前面的挂了后面的顶上、后面的挂了前面的照样能顶回来。某条修好之后不会硬切回来
（线路来回跳，连接和 TLS 都要重建）；真想让它重新当班，把它挪到第一行再点一次「测速并切换」。

**自动切换**（默认开）：后台每 3 分钟把这串线路全测一遍，只有正在用的那条不通了才换。
**它只改内存里的走向，不动你填的地址**——框里永远是你写的那些。

卡右上角的「测速并切换」是手动来一次：所有线路 + 直连**同时测**（一个超时窗口出结果），
在用的那条还通就不动它，断了才按顺序挑下一个。框下面按行号列出结果
（`✓ 24 ms` / `✗ 连接被拒绝…` / `✓ 10 ms · 检索站✗`），改完没保存就点它也行——会先落盘再测。
只通了一个目标的线路写 `✓ 10 ms · 检索站✗`（琥珀色，不判死），鼠标停上去（手机上是长按）看具体原因。

一次请求失败，**重试时自动换下一条**（第 N 次重试走第 N 条线路）；某条刚失败过的会被记 5 分钟，
这期间排到队尾，省得每次请求都先撞一次墙。删掉某行后，之前选中的走向会自动作废，
不会拿着一个已经不存在的地址当第一条。

探测是代理握手（CONNECT），同时试 `api.telegram.org:443` 和 `sukebei.nyaa.si:443`。
**只要有一个通，这条线路就算可用**——机器人和检索站经常不是一起坏的：Clash 里检索站常被单独
分到一个策略组，那个组的节点挂了，就是 Telegram 通、检索站 503。这时候线路显示 `✓ 10 ms · 检索站✗`
（琥珀色），照样会被选来走，不会被判死。真两个都不通才算这条线路挂了。
想让检索站也恢复，得去 Clash 那边给 `nyaa.si` / `sukebei.nyaa.si` 换个能用的节点——
程序这边换线路没用，换了也是同一条 Clash。

两条限制照旧：只支持 `http://` 端口（`socks5://` 会被明确拦下，Clash 的 mixed
端口把前缀换成 `http://` 就行）；内网/本机地址永远直连，不进这个队列。

### 3.3 用手机打开

面板是响应式的，窄屏（≤760px）会自动换一套布局，不用装 App、也不用另开权限：

| 桌面 | 手机 |
| --- | --- |
| 左侧固定侧栏，七个页面平铺 | 汉堡按钮 → 抽屉菜单（七页全在）＋底部标签栏（概览/搜索两格） |
| 表格一行五列 | 每条记录折成一张小卡片，表头文字变成每行左边的小标签（`时间` `标题` `状态`…），长标题自动折行 |
| 表单两列 | 单列，输入框 16px（小于 16px 时 iOS 聚焦会整页放大） |
| 按钮 30 多像素高 | 按钮 ≥42px、开关行 ≥48px，一眼能点准；成组按钮改成一行两个 |
| 顶栏一行（标题 + 说明 + 状态 + 刷新） | 同一行，但刷新缩成 ⟳ 图标、「下载后端」胶囊收起来，说明文字只在概览页露 |
| — | 概览页多一张「快捷开关」卡片 |

**顶栏只占一行**（1.0.32 起不再吸顶，跟着页面一起滚上去）：标题和说明并排，右侧是状态胶囊和刷新。
之前是「大标题 / 说明 / 胶囊」三行叠着，要到 90–110px 才开始有内容；现在桌面 66px、手机 63px 就是第一张卡片。
手机上翻长列表时，顶栏直接滚出屏幕，等于每屏多让出一行。

**顶部的安全区只在「加到桌面独立运行」时才算**（1.0.23）。飞牛 App 用内嵌 webview 打开面板时，
`safe-area-inset-top` 报的是「状态栏 + 原生标题栏」整段高度（≈96px），而网页本来就排在标题栏下面，
顶栏要是照着补一次，标题下面就多一条死白（手机顶栏 152px）。所以顶栏和抽屉只吃 `--sat` 这个变量，
它默认 0，`@media (display-mode:standalone)` 里才取真值。底部不受影响：同一个 webview 里
`safe-area-inset-bottom` 实测就是 0，标签栏照旧躲 Home 条。

「快捷开关」是给手机准备的：**自动投递 / 检索前查字典 / 跳过已下载 / 暂停·恢复机器人 / 迅雷立即重连**，
点一下就落盘（只提交改动的那一小段配置），不用滚到设置页。暂停只影响收消息，正在跑的任务不受影响，
应用重启后恢复成不暂停。最后那格「迅雷」还会把当前连接状态写在按钮左边（`已连接 :5666` /
`未连上` / `点右边重连`），断了就地重连，不用再翻页。

**「最近投递」右上角有个「清除」**（1.0.33）：只把这张表清空，数据库里的记录一条都不删；
清完到下次点「⟳ 刷新」之前不会被切页或轮询又铺回来，不然看着像没生效。

**每条记录都能把磁力抄走**（1.0.38）：行尾的「复制」抄这一条；前面勾几条（或用右上角「全选」），
再点「复制 N 条」，一次拿到多行，一行一条。迅雷额度用完了要去套件里手动加时，就靠它把链接攒起来——
不用再翻 Telegram 聊天记录。只有 infohash 的老记录会现拼一条标准 `magnet`，照样能用。

手机上这条记录只占**两行**（勾选 + 整行标题 / 时间·后端·状态 + 复制），任务号那列在窄屏直接收起，
所以「最近投递」不会一列一行地往下堆。

**防误操作的几处设计**：

- 会**覆盖已有配置或整份规则**的动作先弹确认：保存 rules.json、自动侦测并连接、从已有任务找下载目录、
  重连机器人、删除规则。确认框里固定是「取消」在下、「继续」在上，拇指容易碰到的位置留给取消。
- 有改动没保存时**切页会拦一下**，并浮出「还有改动没保存 / 放弃 / 保存」的提示条——表格长的时候不用再滚回顶部找保存按钮。
- 请求进行中的按钮会转圈并锁住，挡住连点造成的重复提交。

**搜索页**（桌面和手机同一套）：关键词是多行输入框，粘一整段 Telegram 消息能看见自己在粘什么。
右边是**两个动作**，不再让人猜「搜索」到底搜哪段文字：

| 按钮 | 干什么 | 什么时候用 |
| --- | --- | --- |
| **直接搜索** | 把框里这行字原样当关键词发给站点，配上「更多选项」里的分类/排序/做种 | 已经知道要搜什么词 |
| **解析后搜** | 先按机器人那套判定解析这段消息（自带磁力 / FC2 编号 / 整段检索），**把判定结果摆出来**，再用判定出的查询和**规则里的条件**去搜 | 想确认「机器人收到这条会搜什么」 |

解析结果面板里写清楚四件事：判定是什么、抓到的磁力/FC2 编号、真正发给站点的查询串、命中了哪条规则
（以及这条规则的分类/排序/最少做种）。自带磁力的消息**一次检索都不发**，直接把磁力列出来，旁边就是「投递」。

「粘贴」把剪贴板内容填到光标处——内网 `http://` 打开时浏览器不允许读剪贴板，这时它会聚焦输入框并提示
长按粘贴，不会变成点不动的死键。回车即搜（等于直接搜索）、Shift+回车换行；分类 / 排序 / 最少做种 / 条数
和「测试站点连通 / 网络诊断」都收进默认收起的「更多选项」，收起时标题上写着当前条件
（`全部 · 按做种数 · 做种≥1 · 10 条`），改一个立刻跟着变。

手机上能做的事和电脑完全一样：连迅雷、抓令牌、跑诊断都是 NAS 后台在干活，浏览器只是个遥控器
（原因见 [docs/迅雷接入.md](docs/迅雷接入.md) 的「在手机飞牛 App 里点，和电脑浏览器有区别吗」）。

## 4. 迅雷接入

**只有一种接法**：飞牛网关 `/cgi/ThirdParty/xunlei/index.cgi`，对应应用中心里的官方「迅雷」套件。
1.0.31 起不再提供「2345 面板」这个选项——那台机器上根本没有独立面板，`mode` 的默认值却一直是
`panel`，于是谁都没选过、却一直在打一个没人监听的端口（`errno 111`）。

需要两样：`pan_auth`（迅雷自己的登录态，新版套件把它内联在首页里，程序自己会读）和
一份飞牛登录 Cookie（新版飞牛认的是其中的 `fnwg_token` + `ost`）。

**不用自己配**：服务启动时会自动侦测网关端口（飞牛 Web 端口被改过也能找到）、复用你当前飞牛的
登录态、并在迅雷自己的目录里找令牌；打通就把端口与令牌写进配置并复测。之后从飞牛桌面打开一次面板，
浏览器带来的登录态会再触发一次自动连接。连不上就点面板里的「立即重连」，不用重装、不用重启。
细节见 [docs/迅雷接入.md](docs/迅雷接入.md#0-先试自动侦测)。

不想折腾迅雷？把后端换成 `aria2` 或 `qbittorrent`（或 `none` 只回传磁力）即可，其余流程不变。

## 5. 消息怎么被判定

每条消息进来先过 `app/tmb/intake.py`，**按顺序**问三个问题，命中就停：

| 顺序 | 条件 | 动作 | 联网？ |
| --- | --- | --- | --- |
| 1 | 有 `magnet:?xt=urn:btih:...`（40 位 hex 或 32 位 base32 都认） | 直接投递给迅雷，一条消息最多投 3 条（`download.max_magnets`） | 不联网 |
| 2 | 没有磁力，但出现 `FC2` 字样且后面跟着编号 | 只把编号（优先 7 位）当检索词，去 sukebei 搜，取第一条投递 | 检索 |
| 3 | 两样都没有 | 整段消息走关键词分拣，再检索投递 | 检索 |

几个刻意的细节：

* 两个特征同时存在时**磁力优先**。比如原文既有 `FC2PPV-4999948` 又有磁力，就直接投被给出来的那条，回复里会注明「另有 FC2PPV-4999948，本次用磁力」。
* FC2 编号认这些写法：`FC2PPV-4999948`、`FC2-PPV-1234567`、`fc2 ppv 1234567`、`FC2PPV_7654321`、`FC2 123456`。一段话里出现多个编号时优先 7 位的那个。
* 有 `FC2` 字样但后面没编号（比如「FC2 新作」）→ 退回第 3 条按整段检索，不会去搜一个空编号。
* 磁力末尾粘的中文标点、Telegram 转义出来的 `&amp;`、大写的 `MAGNET:?XT=` 都会被收拾干净；同一个 infohash 重复粘贴只投一次。
* 截断的磁力（infohash 不足 40 位）不投，回复里明确写「这条没认出来」，然后按文本走第 3 条。

想确认某条消息会走哪条路，不用真发：面板 → 搜索测试 → 粘进去 → **解析后搜**，判定、查询串、命中规则、
磁力/编号会一起列出来（自带磁力的连检索都不发），或

```bash
python3 /var/apps/tgmagnet/target/main.py --parse "FC2PPV-4999948 某标题"
python3 /var/apps/tgmagnet/target/main.py --parse "贴一段带磁力的消息" --send   # 真跑一遍
python3 /var/apps/tgmagnet/target/main.py --parse "ABC-123 甲" --send --force  # 无视历史字典
```

`--parse` 只做判定不联网；加 `--send` 才会真的检索并投递。判定细节、边界情况与清理规则见 [docs/消息分拣.md](docs/消息分拣.md)。
每个开关管到哪一步、「关掉自动投递之后还会发生什么」，见 [docs/开关与信息流.md](docs/开关与信息流.md)。

### 5.1 关键词规则

第 3 条分支用到的规则：面板抽屉 → 关键词规则，可视化编辑；也可以直接改 `etc/rules.json`。字段：

| 字段 | 说明 |
| --- | --- |
| `match.any` | 命中词，任一出现即命中（中文子串匹配，`番` 能命中「番剧」） |
| `match.all` | 必须全部出现的词（可选） |
| `match_regex` | 正则，额外加分（可选） |
| `strip_words` | 取词时丢弃的词，如「番剧」「求」「下载」 |
| `query_template` | 检索词模板：`{keywords}` 拼好的关键词、`{kw1}` 第一个词、`{raw}` 原文 |
| `category` | sukebei 分类：`0_0` 全部、`1_1` Anime、`1_2` Doujinshi、`1_3` Games、`1_4` Manga、`1_5` Pictures、`2_1`/`2_2` Real Life |
| `sort` | `seeders` / `downloads` / `date` / `size` |
| `filter` | `0` 全部、`1` 仅非重制、`2` 仅可信组 |
| `min_seeders` | 做种下限，低于直接丢弃 |
| `min_size_mb` / `max_size_mb` | 体积区间，0 表示不限制 |
| `prefer_words` | 命中加分（如 `1080p`、`中字`、`合集`） |
| `exclude_words` | 命中即丢弃（如 `sample`、`预告`） |
| `limit` | 取回条数 |
| `auto_download` + `pick` | 是否自动投递、投递第几名 |

分拣流程：所有启用规则算分 → 取最高分那条 → 用它的参数检索。都不命中时走 `default` 兜底规则（默认模板 `{keywords}`）。

内置规则有 `fc2`、`show`（影视/剧集）、`book`（图书/漫画）。`fc2` 那条负责 FC2 分支的分类、做种下限与 `limit`，检索词固定为编号（`query_template: {kw1}`）；把它删了也能跑，会退回兜底规则。老版本升级时 `rules.json` 会自动补上缺失的内置规则，你自己加的规则与顺序不动。

## 6. 回复长什么样

```
🎯 影视/剧集　命中：剧、番
🔍 查询：某作品 1080p 中字
🧩 关键词：某作品 / 1080p / 中字
📦 命中 5 / 抓取 20

✅ 1. 🟢 某作品 1080p 中字 合集 [Group]
　　⬆️301 ⬇️9900 · 1.2 GiB · 2 天前　做种充足，标题完全命中，可信发布
　　↳ 已投递 xunlei · #1234567890
2. 某作品 1080p 中字 [AnotherGroup]
　　⬆️42 ⬇️1200 · 860.0 MiB · 5 天前　偏好词:中字
```

`🟢` 表示这条对应站点列表里的绿底行（可信发布者），排序时会给它加分。
下面跟一排按钮：`⬇️ 1` … `⬇️ 5`（单独投递）、`🔁 重搜`、`📋 全部磁力`。

消息自带磁力时不走上面那套，回复直接报投递结果（已经投出去就不再挂「⬇️」按钮，避免重复投）：

```
🧲 直接投递　消息自带磁力，跳过检索
另有 FC2PPV-4999948，本次用磁力、不用编号
📥 共 1 条磁力

✅ 1. FC2PPV-4999948 拥有25万粉丝的知名网红
　　E8BE27D6280895F4838832CF84D90451B69B3AFC
　　↳ 已投递 xunlei · #1234567890

成功 1 / 1
```

**关掉「自动投递」之后，两种回复都会明说「没下」**，原因指认到具体开关：

```
📦 命中 5 / 抓取 20
⏸ 自动投递已关闭：只列结果，要点下方 ⬇️ 按钮才下载。
```

```
🧲 直接投递　消息自带磁力，跳过检索
⏸ 自动投递已关闭，这几条还没进迅雷，点下方按钮才下
📥 共 1 条磁力

⏸ 1. FC2PPV-4999948 拥有25万粉丝的知名网红
　　E8BE27D6280895F4838832CF84D90451B69B3AFC
　　↳ 待确认，点 ⬇️ 1 投递

想恢复「收到就下」，去面板概览页把「自动投递」打开。
```

FC2 分支的回复开头是 `🧲 FC2 · FC2 编号`，紧跟一行 `🔍 查询：4999948`，让人一眼看出只搜了编号。

## 6.1 历史字典：这个是不是已经下过

在「历史字典」标签里填几个目录（一行一个），点**开始分析**。它会记住目录下的文件夹名与文件名，
之后每次搜索都先拿关键词比一遍：

| 情况 | 回复里你会看到 | 会不会投递 |
| --- | --- | --- |
| 字典里有同名的、且现在还在 | `📚 库里已有` + 完整路径 | **不检索、不投递**（发 `/force 关键词` 才强制重下） |
| 曾经有、后来被删了 | `🗑 曾经有，现在没了` + `2026-10-02 14:11 发现已删除` | **同样不检索、不投递**（发 `/force 关键词` 才继续） |
| 没比中 | 无额外提示 | 照常检索投递 |

「已删」和「已存在」按同一套规矩走：**这两种情况都要 `/force` 才能继续**。记录还在，说明这片子
以前下过，删掉多半是主动清理，再投一次大概率白下——所以默认拦住，把「什么时候发现被删的」摆给你看，
要不要重下由你决定。弱匹配（名字只是部分重合）仍然只提示、不拦。

**「发现时间」的确切含义**：是**扫描那一刻**发现它不在了，不是你删除它的时间。程序拿不到删除时刻，
只能记录「我什么时候发现的」。

**记录不会消失**：扫描只做快照对比，从不删字典条目。删掉重建的文件会重新标成「存在」，
但 `deleted_ts` 与累计消失次数留着，所以「曾经下过又删了」这件事一直可查。

**两种保护**，避免误清：

* 目录整体读不到（卷没挂上、权限变了）→ 该目录的条目**一条都不标**删除，报告里给出警告。
* 目录还能读但条目骤减（低于原来的 40%）→ 同样按「疑似不可访问」处理，只警告不标记。

**重复分析**：按「归一化名 + 去掉扩展名/`(1)`/`副本`/`copy` 尾巴」分组，同一份东西出现在两个位置就会列出来；
组内体积也一致时判定为「基本可以确定重复」。目录与它自己的同名文件不算重复。

命令行同样可用：

```bash
python3 /var/apps/tgmagnet/target/main.py --lib-scan                 # 分析配置里的目录
python3 /var/apps/tgmagnet/target/main.py --lib-scan --roots /vol1/1000/Downloads
python3 /var/apps/tgmagnet/target/main.py --lib-lookup "FC2PPV-4999948"
python3 /var/apps/tgmagnet/target/main.py --lib-dups
```

细节与匹配口径见 [`docs/历史字典.md`](docs/历史字典.md)。

## 9. 常见问题

**列表里淡绿色的那行是什么？磁力怎么直接取？**
绿底是站点标记 `trusted`（可信发布者），**不是「最热门」**——做种数可能反而更少。磁力就在 Link 列 🧲 图标指向的 `magnet:?xt=urn:btih:…`。完整机制、三种取法与踩坑点见 [`docs/磁力提取.md`](docs/磁力提取.md)。

**搜不到结果 / 提示无法访问站点**
NAS 到 `sukebei.nyaa.si` 不通，或站点弹 Cloudflare 人机验证。面板里点「测试站点连通」确认；必要时在设置里填代理（支持 `http://host:port`）。

**迅雷测试连接能通但没有设备空间**
`pan_auth` 过期，或迅雷面板没登录迅雷账号。重新登录面板后重新拷贝令牌。官方套件请确认迅雷账号已绑定。

**投递报 `invalid token`**
先看状态码：**HTTP 200 + 13 字节纯文本**说明是**飞牛网关在拦登录 Cookie**，不是迅雷云在拒绝
`pan_auth`。新版飞牛（迅雷套件 3.23.5 起）要的是 Cookie 里的 `fnwg_token` + `ost`，而且
**只要还带着老的 `fnos-token` 就整条拒**——值和位置都不看。1.0.42 起设置页那格改成
「飞牛登录 Cookie」，F12 复制 `Cookie:` 整行粘进来即可，程序会自动剔掉惹事的那一项；
从飞牛桌面点开面板也会自动带上。

先点面板「测试连接」，返回里会写清**是哪个令牌**（1.0.42 起用套件首页做探针，不再靠猜）：

* `culprit=pan_auth` → 登录 Cookie 是好的，是迅雷那条 `pan_auth` 被云端作废了。程序会自动
  打开套件首页、把内联的 `uiauth()` 读回来换上去重试，一般不用你动手；仍失败才点「立即重连」。
* `culprit=fnos_token` → 飞牛登录 Cookie 不行（见上）。从飞牛桌面打开一次面板，或 F12 粘一次。
* `culprit` 为空 + `auth_evidence` 说探针没发出去 → 网络 / 端口问题，先别怪令牌。
* `pan_auth` 是 JWT，「测试连接」会直接解出过期时间：`迅雷令牌　已于 5 小时前过期　← 就是它`，
  或 `还有 3 天后到期`。前者去重新登录迅雷套件，后者说明令牌没问题、别再折腾它。
* 会自动续期吗：**不会自己续**（续期握在迅雷手里，程序没有你的迅雷密码、也没有刷新接口），
  但会「接住」迅雷续好的那个——剩不到 48 小时时每 6 小时读一次套件首页，拿到过期时间更晚的
  就写进配置并在回复里注明；拿不到就在剩 72 小时时把面板顶栏挂成可点的「迅雷令牌 还有 2 天后到期」。
  三个窗口是 `download.xunlei.token_warn_hours / token_watch_hours / token_retry_hours`。
* 报错里夹着一串 `�` / 乱七八糟的符号？那是**压缩响应被当文本读**：1.0.14 起请求不再主动要压缩，
  头缺失时按字节特征兜底解 gzip/zlib，还会回退 GB18030；真解不出就只记 hex 进日志，不再把乱码发到聊天里。
* 报 `HTTP 400` 说明网关不接受请求体（字段缺失/类型不对），跟令牌无关，报错会列出本次发了哪些字段。
* `culprit=token_ok` → 令牌是通的，被拒的是「建任务」这一步。先重抓 `pan_auth`，再换个磁力排除资源本身；
  原始响应在 INFO 日志里就有（`迅雷建任务被拒 … 原始响应：{...}`），改成 DEBUG 还能看到完整请求与响应，
  令牌与磁力哈希已自动打码。
* 磁力能解析出来说明云端 `pan_auth` 有效，这时再报鉴权失败会自动改用「只留必填字段」的
  最简请求体重试一次（`mime_type` / `sub_file_index` / `file_size` 有的版本不认）。
* 代理算不算影响：内网地址一律直连，1.0.13 起也认 `100.64.0.0/10`（WireGuard/Tailscale 常用段）；
  「测试连接」会多一行「线路」告诉你这次到底直连还是经代理。

1.0.10 及以前是按模式一律怪 `fnos-token`，于是「重登飞牛 → 还是同样的错 → 再重登」循环。
1.0.11 改成「同一接口带/不带 Cookie 比回答」，但这个办法在新版飞牛上**必然判反**：
网关见到 `fnos-token` 就整条拒，两次当然一样，于是被读成「网关不看 Cookie → 那就是
`pan_auth` 过期」。1.0.42 换成拿**不需要 `pan_auth` 的套件首页**当探针，才把这个环打破。

重扫时会把手上几串候选令牌都试一遍（套件首页内联的、浏览器送来的、配置里的、磁盘捞到的），
第一个打通的算数；投递失败也会自动重抓一次并立刻重试，成功时回复标注「本次令牌已自动更新」。
详见 [`docs/迅雷接入.md`](docs/迅雷接入.md)。

**投递报 `parent folder not found`**
面板「下载目录 id」对不上当前迅雷：换过下载设备、重装过迅雷、那个目录被删了，或者把路径当 id 填了进去
（迅雷要的是目录 id，`/vol1/1000/Downloads` 这种不算）。

* 最省事：把「下载目录 id」**留空**，任务落到迅雷默认下载目录；
* 要固定目录：迅雷面板 → 文件 → 点进目标目录 → 复制地址栏 `parent_folder_id=` 后面那串（必须是当前设备的）。

默认开着「目录 id 无效时改用默认目录」：撞到这个错会依次再试「去掉目录参数（默认目录）→
用迅雷自己用过的目录」，哪一步成就停在哪，回复里写明用的是哪种。**失败时不会改你的设置**；
只有投递成功、且用的是从任务列表里找回的目录时，才把这个 id 记进配置。

卡片上的「从已有任务找下载目录」按钮会列出迅雷任务列表里它自己写过的目录 id，
点一下即写入设置（命令行：`--xunlei-folder` / `--xunlei-folder --apply`）。

**投递报一串数字（比如 `error_code: 9126`）**
迅雷没给文字说明，只回了个码。公开查得到的码（107 / 108 / 112 / 131 / 202 / 2）会照实翻译；
查不到的（`9126` 属于这类，官方没有公开对照表）不瞎猜，直接按「可能是目录问题」走上面那套重试，
多数情况任务就投进去了。都失败才会报错，并给出三条自检方向 + 原始响应。

**投递成功但迅雷里没任务**
多文件种子可能被文件筛选规则裁掉了（回执里会写「38 个文件里挑了 12 个」，跳过的是哪几类一目了然）；
也有可能是 NAS 版迅雷的**每日任务数限制**（非会员较少），任务会被拒绝并回传错误信息。

**多文件种子只想下正片和字幕**
抽屉 → 下载与迅雷 → 「文件筛选」开关打开（1.0.25 起默认就是开的）→ 勾「视频」「字幕」。
默认还会跳掉小于 100 MB 的文件（挡预告片、样片），字幕和说明不受这条限制——
字幕天生几十 KB，真按 100 MB 筛会把字幕全删。

这条规则是**全局**的：自动投递、关掉自动投递后点「⬇️ 现在下」补投、以及直接发磁力链接，
走的是同一份配置、同一个判定函数（`tests/test_filter_scope.py` 把四条入口各跑一遍，
断言发出去的 `sub_file_index` 一模一样）。唯一的例外是 `download.fallback` 里的
aria2 / qBittorrent 接管了那一次——它们不做文件选择，回执会明说「文件筛选只对迅雷生效」。
规则说明、跳过原因、回执文案见 [docs/文件筛选.md](docs/文件筛选.md)。

**筛选明明设了，投递还是全下了**
四种已知情况，回执里都会明说：① 顶上的「文件筛选」开关被关了，多文件种子一律全下；
② 规则把文件全筛掉了，程序自动改回全选（宁可多下，也不建一个没有文件的空壳任务）；
③ 撞上鉴权兜底或换成了 aria2/qBittorrent，那次请求里没有 `sub_file_index`，筛选没生效；
④ 这条磁力连文件清单都没拿到（迅雷只回一个目录节点、种子又下不下来）——回执会写
「没拿到文件清单，这次是整个种子全下」，认了，不装。

**想知道某条磁力到底被认成了几个文件**
到**搜索页**把磁力粘进去：搜索键会自己变成「解析磁力」，点一下（或直接回车）就列出
认出几个文件、从哪个来源认出来的（迅雷接口 / 种子文件）、按当前规则 ✓✗ 每个文件、
以及最后发给迅雷的 `sub_file_index`。只问不投，不会建任务。
1.0.26 起，迅雷只回一个「目录节点」不再等于全下：程序会退到 `.torrent` 的 `info.files`
去认清单（顺序就是 `sub_file_index` 的序号）；1.0.27 又修了那条路本身——代理把响应
掐在半路时用 `Range` 续传，而不是整下重来（重来多少次都断在同一处）。
1.0.28/1.0.29 才把真身挖出来：清单**一直都在第一次响应里**，只是被 `list` 和目录节点的
`dir`（是对象、不是路径）包了两层，老代码只认平铺的 `resources` 就把它当「空目录」丢了。
现在这两层都剥得开，一次请求、零外网就能拿到带 `file_index` 的真实清单；
只有别的版本真把 `dir` 给成路径时，才会去钻目录 / 下种子兜底。
1.0.30 加了端口兜底：连不上就自动改试另一个网关端口（日志写明换到了哪）；
1.0.31 干脆删掉「2345 面板」这个选项与端口输入框——只有官方套件一种接法，
端口由启动时的自动侦测决定，面板上只显示「已连接 · 网关 :5666」和一个「立即重连」。
预览已经认出多于一个文件时也不再跑外网下种子。

**装了飞牛官方市场的迅雷，还要手抄令牌吗？**
先点面板里的「立即重连」（或 `--detect --apply`）；服务启动时本来就会自动连一次。它会认出官方套件的网关地址与端口，并复用你当前飞牛的登录 Cookie，多数情况一次就通，`pan_auth` 都不用填。结果里会直接写清缺什么：`需要飞牛登录 Cookie（新版飞牛要 fnwg_token + ost）` 表示没拿到登录态（通常是直接用 IP 打开面板的），从飞牛桌面进一次再点；`缺 pan_auth` 才需要手抄一次。面板「令牌来源」那一行会显示手上这串是浏览器带来的、手填的，还是多久前抓的。

**历史字典说「库里已有」，但我确实想再下一份？**
发 `/force 关键词`（或 `/force 一段话`），跳过字典直接检索投递。

**字典说「曾存在，已删除」，也要 `/force` 吗？**
要。已删和已存在同一套规矩：默认都拦，回复里会写清「X 时间发现已删除」。确认要重下就发
`/force 关键词`。想改成「已删的只提示、照常投递」，把「历史字典」里的
「命中『曾存在已删』也不投递」关掉即可（`library.skip_deleted`）。

**扫了目录但一条都没记住？**
先看报告里的警告行：`目录不存在或不可读` 说明路径写错或该目录对应用户没有读权限（fnOS 里本应用以哪个用户跑，
就用哪个用户能读的路径）。另外 `分析深度` 默认只走 3 层，目录结构很深的话要调大；超过「最多记录条目」会被截断并提示。

**qBittorrent 提示「登录失败」**
先跑一次探测，它会打出 qB 的真实响应并直接给结论：

```bash
python3 /var/apps/tgmagnet/target/main.py --probe qbittorrent
```

以前这个错一律只写「登录失败」，现在会区分到底卡在哪一步：

| 探测输出的原因 | 真正的问题 | 怎么修 |
| --- | --- | --- |
| `账号或密码不对（qB 返回 Fails.）` | 凭据错 | qB 默认 `admin/adminadmin`；v5 起首次启动会打印**随机临时密码**到容器日志 |
| `Host header 校验 / CSRF 拦截（HTTP 401）` | 用 NAS 的 IP/域名访问，不在 qB 白名单 | qB 设置 → Web 界面：关掉「启用 Host header 校验」，或把「服务器域名」加上该 IP（可填 `*`） |
| `被拒绝（HTTP 403）` | 密码试错太多次被临时封 IP；或反代没转发 `/api/v2/auth/login` | 等 15 分钟或重启 qB；检查反代与「仅 HTTPS」开关 |
| `接口不存在（HTTP 404）` | 端口上不是 qB，或子路径没带前缀 | 确认端口（默认 8080），反代挂在 `/qbt` 之类要写进地址 |
| `登录返回 Ok，但会话没生效` | `Set-Cookie` 被反代改写/丢弃 | 直连 WebUI 端口，或让反代透传 Cookie |
| `连不上 …：连接被拒绝` | qB 没启动 / 端口不通 / 只监听 127.0.0.1 | 启动 qB、放行端口；跨机器访问需让它监听 `0.0.0.0` |

顺带两点：**本机与内网地址会自动直连**（不会把 `127.0.0.1` / `192.168.x` 交给代理绕一圈再失败），qB 在外网时才需要填「代理」；「添加后暂停」「标签」也在面板里可配。

**日志一直刷 `getUpdates 请求失败: HTTP 409`**
不是网络问题，也不是 token 填错。Telegram 的 409 只有一个含义：**同一串 Bot Token 还有另一个地方在 `getUpdates`**。
一个机器人只能有一处收消息，两处同时收会互踢，后到的把先到的顶掉。

| 现象 | 原因 | 怎么修 |
| --- | --- | --- |
| 刚点过「重连」或保存设置后冒一两条 | 旧的长轮询还没退，新的把它顶掉——自己人打架 | 不用管，1.0.18 起静默自愈 |
| 一直刷，每分钟一条 | 旧进程没退干净（重装、重启应用后最容易） | 应用中心「停止」→ 等几秒 →「启动」 |
| 一直刷，别处也装过一份 | 同一 token 在两台设备/两个容器上跑 | 只留一处，或换一个 bot token |
| 一直刷，且本机只跑着一份 | 以前给这个 bot 设过 webhook | 会自动清；也可手动 `curl -X POST "https://api.telegram.org/bot<token>/deleteWebhook"` |

1.0.18 起：撞一次先等 3 秒重试（大概率是刚重连）；连着撞两次才判成外部冲突——先查 `getWebhookInfo`，
有 webhook 就清掉改回长轮询，没有就等 5 分钟再来一次，且**只告警一次**、不再刷屏；面板侧栏那行会变成
「轮询冲突 · 同一 Bot Token 另有实例在收消息」，恢复后自动消失。
另外两处兜底：`cmd/main` 停/启时按 `/proc` 精确匹配清掉同一个安装目录下的残留 `main.py`；
新进程抢不到面板端口时**直接退出**，不再「面板起不来但机器人照跑」，避免两个实例抢同一个 token 把消息分走。

**改了日志级别没生效**
日志级别在启动时读取，改完重启应用。

**面板打不开**
端口 8470 被占用，或 `cmd/main` 的 `status` 看进程没起来 —— 去 `{var}/logs/stdout.log` 看启动报错（最常见是没找到 python3）。1.0.18 起端口被占用会直接写一行「本机很可能已经有一个磁力管家在跑」并退出，不会硬起第二份去抢 Bot Token。装了非标准路径的 Python 时，用环境变量指定解释器再启动：

```bash
TMB_PYTHON=/opt/python3/bin/python3 ./cmd/main restart
```

**会不会重复下载**
默认同一 infohash 30 天内不重复投递，可在设置里改「去重天数」。

## 9.9 面板显示的版本号

面板、日志首行、HTTP `Server` 头里的版本号都来自 `tmb/_build_version.py`，这个文件由
`tools/build_fpk.py` 按 `manifest` 的 `version` 生成，打完包还会核对包内版本与 manifest 一致。
所以「飞牛应用中心是 1.0.16、面板显示 1.0.11」这种事不会再发生——1.0.15 之前它是硬编码常量，
忘了改就一直显示旧版本，很容易让人以为覆盖安装没生效。

## 10. 合规说明

本项目只是把「消息 → 关键词 → 检索 → 下载器」这条链路自动化，本身不托管、不分发任何内容。检索结果来自第三方站点，下载由你配置的下载器完成。请自行确认使用行为符合所在地法律法规及站点条款；作者不对具体使用行为负责。
